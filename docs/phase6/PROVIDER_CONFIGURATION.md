## Final confirmation

The model cannot prove full playback or independently authorize a purchase. No transcript, tool boolean or post-call analysis sets `relayReviewReady`. Existing relay playback safeguards remain intact.

`review_order` generates the exact backend review plus an 80-bit random, ten-minute maximum review code, grouped into five blocks of four hexadecimal characters. Brittany directs the customer to the returned `/confirm` address and reads the code. The page shows name, items, quantities, notes, subtotal, promotion discount, tax and total. The customer must check their name and complete-order confirmation. Notifications default to none and require a separate explicit opt-in. Only the page's same-origin, HttpOnly-cookie/CSRF-bound submission commits the existing order transaction.

Codes expire at the earlier of ten minutes or session expiry. Cart/name/notes/preference changes invalidate them; server price/stock/promotion changes require a fresh review. Keep the call connected during checkout. A signed terminal callback or expiry blocks a new order, while an already committed receipt remains retrievable. The post-call callback arrives after provider analysis, so it is not instantaneous hangup evidence. Lost terminal callbacks leave a bounded window until the thirty-minute session expiry; no API claims stronger liveness proof.

The code-entry journey is functional in Chromium, but verbal-code usability, a second device/mobile call, real audio, interruptions and language quality still require controlled human telephone acceptance. A customer unable to use the review page must be referred to restaurant staff; Brittany must not bypass it.

## Signed terminal webhook

Create an agent-scoped ElevenLabs HMAC post-call webhook to `POST https://APPROVED_APP_HOST/api/elevenlabs/post-call`. Store its generated secret as `ELEVENLABS_POST_CALL_SECRET`, separately from initiation and tool keys. Enable `transcript` and, where used, `call_initiation_failure`; leave audio/unredacted-audio events disabled. The handler authenticates the raw body using `elevenlabs-signature: t=<unix-seconds>,v0=<HMAC-SHA256>` over `<timestamp>.<raw-body>`, with a thirty-minute time window, then matches the configured agent and bound conversation. Duplicate terminal notifications are harmless. Raw transcripts, audio, analysis and secret dynamic variables are neither stored nor logged. Bodies above 1 MiB are refused; validate the account's retention/redaction and payload sizes before activation.

## Telnyx SMS and optional ready calls

Use the existing notification worker and callback handlers. Required SMS configuration: `TELNYX_API_KEY`, `TELNYX_PHONE_NUMBER`, `TELNYX_PUBLIC_KEY`, `TELNYX_MESSAGING_PROFILE_ID`, `PUBLIC_APP_URL`, `STAFF_SESSION_SECRET`. Keep `SMS_DELIVERY_ENABLED`, `SMS_REGISTRATION_VERIFIED`, `SMS_SENDER_VERIFIED` false until an operator verifies the sender, Messaging Profile, applicable A2P registration and STOP/START/HELP provider responses. The boolean flags are operator attestations, not automated proof of carrier approval.

Set the profile's primary webhook to `POST https://APPROVED_APP_HOST/api/telnyx/messaging`, Ed25519 signatures enabled. The handler verifies timestamp and exact signed body, deduplicates receipts, updates delivery state, and applies ordered STOP/START events. HELP responses are provider-managed; configure and verify them rather than creating duplicate application replies. STOP blocks pending SMS for the customer. Order state, consent, channel, suppression, hourly limits and delivery gates are rechecked under locks before submission.

Templates use the saved restaurant name, pickup name, eight-character order reference and database total. Petra Cafe example:

```text
Petra Cafe: Hi [name], your order #[number] has been received. Total: [total]. Pay at pickup. Reply STOP to opt out.
Petra Cafe: Your order #[number] is now being prepared. Reply STOP to opt out.
Petra Cafe: Your order #[number] is ready for pickup. Thank you! Reply STOP to opt out.
```

Only definite HTTP 429 without an identifier retries automatically, with a one-minute minimum delay and at most three submissions. Network exceptions, malformed successful responses and server errors stay uncertain for operator reconciliation; they are never blindly resent. Disabled delivery defers without consuming the send-attempt budget. Submitted/delivered jobs are not resubmitted. Rapid kitchen changes suppress obsolete updates rather than sending misleading old status messages.

The optional ready call uses the existing Telnyx TeXML fallback with Polly.Joanna-Neural, the actual saved order reference, recorded per-order call consent and one durable job created only when the order reaches `completed`. It requires `OUTBOUND_UPDATES_ENABLED=true` and `TELNYX_TEXML_APPLICATION_ID`. Each callback includes a per-job HMAC token and also requires Telnyx Ed25519 verification at `/api/telnyx/call-status`. ElevenLabs outbound Brittany SIP was **not** established or accepted here; this fallback must not be described as Brittany. Leave calls disabled until the user approves provider acceptance and chooses/accepts the fallback voice.
